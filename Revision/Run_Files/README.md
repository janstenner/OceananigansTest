# Revision Run Files

This directory contains the four standalone entry points for revision package 2:

- `FixedIC_MAT.jl`
- `FixedIC_IPPO.jl`
- `VaryingIC_MAT.jl`
- `VaryingIC_IPPO.jl`

Each file initializes its environment, policy, and hook when included. Training
is started explicitly with `train(...)`. Existing JLD2 `save` and `load`
routines are retained. By default, artifacts are written below
`Run_Files/outputs/<scriptname>`. Set `REVISION_RUN_DIRECTORY` before including
a file to use an experiment-specific directory.

`ENV` is Julia's string-to-string view of the process environment.
`REVISION_RUN_SEED` is an optional environment variable read from that mapping;
it is not defined elsewhere in the project. If it is absent, the run file draws
a random seed from `0:99_999`, matching the manual-run behavior of the source
files. A higher-level Julia runner can set a reproducible seed before inclusion
with `ENV["REVISION_RUN_SEED"] = "123"`.

The protocol-specific model sizes from the source files are intentionally not
forced to match: Fixed-IC MAT uses model/head/FFN dimensions
`32/16/32`, while Varying-IC MAT uses `44/22/44`; both use two heads.

The IPPO files implement parameter-sharing IPPO: one shared actor/critic pair is
applied to every actuator column.

Their widths are chosen to match the corresponding MAT parameter counts as
closely as the integer hidden-layer sizes allow, while enforcing
`nna_scale == 2 * nna_scale_critic`: Fixed-IC IPPO uses `2.8/5.6`
(critic/actor), and Varying-IC IPPO uses `4.2/8.4`.

## Varying initial conditions

The Varying-IC files include `VaryingIC_Corpus/VaryingICCorpus.jl` directly.
Their hook-compatible initializer has the form

```julia
generate_random_init(;
    split=initial_condition_split,
    rng=initial_condition_rng,
    base_seed=nothing,
    mirror=nothing,
    offset=nothing,
)
```

Higher-level experiment files may set `initial_condition_split` or call the
initializer with an explicit split and any combination of fixed or sampled
`base_seed`, `mirror`, and `offset`. It returns
`(result, split, base_seed, mirror, offset)`. The hook uses only `result`.

No corpus entries are generated by these run files.
